# PdfBuilder devuelto en lugar de Response al descargar cotización

**Date:** 2026-08-17 01:14
**Files:** app/Infrastructure/Pdf/SpatieQuotationPdfGenerator.php, tests/Feature/QuotationPdfDownloadTest.php
**Severity:** high

## Problem

`GET /projects/{project}/cotizaciones/{quotation}/pdf` devolvía HTTP 500:

```
TypeError: App\Infrastructure\Pdf\SpatieQuotationPdfGenerator::download():
Return value must be of type Symfony\Component\HttpFoundation\Response,
Spatie\LaravelPdf\PdfBuilder returned
```

## Root Cause

En `spatie/laravel-pdf` 2.12.1, `PdfBuilder::download()` no genera ni devuelve un HTTP Response: configura headers (`Content-Disposition: attachment`) y retorna `self`. `PdfBuilder` implementa `Illuminate\Contracts\Support\Responsable`; Laravel solo llama `toResponse($request)` cuando el builder se retorna desde un controlador. El puerto `QuotationPdfGeneratorInterface::download()` exige `Symfony\Component\HttpFoundation\Response`, así que PHP rechazaba el `PdfBuilder` antes de que el framework pudiera convertirlo.

## Solution

Se mantiene Spatie Laravel PDF y el driver `dompdf`. Tras `->name($filename)->download()`, se llama a la API real `PdfBuilder::toResponse(request())`, que genera el binario PDF y retorna `Illuminate\Http\Response` (subclase de `Symfony\Component\HttpFoundation\Response`) con `Content-Type: application/pdf` y `Content-Disposition: attachment`. Se añadió logging `[FIX]` alrededor de la conversión.

## Prevention

- No asumir que un método llamado `download()` de una librería PDF devuelve `Response`; leer el return type de la versión instalada en `vendor/`.
- Si una clase es `Responsable`, convertirla explícitamente con `toResponse($request)` cuando el contrato propio exige `Response`.
- Cubrir la ruta de descarga PDF con un test HTTP que aserte status 200, `application/pdf`, `attachment` y magic bytes `%PDF`.
