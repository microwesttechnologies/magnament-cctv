# Login de técnico con correo y cédula rechazado

**Date:** 2026-08-17 16:35
**Files:** app/Http/Controllers/Auth/AuthController.php, app/Http/Controllers/Technician/TechnicianAuthController.php, app/Application/ServiceOrder/TechnicianCredentialAuthenticator.php, app/Http/Middleware/EnsureTechnicianMobile.php, resources/views/auth/login.blade.php, tests/Feature/ServiceOrderModuleTest.php
**Severity:** high

## Problem

El técnico no podía entrar con correo y cédula. El formulario de oficina (`/login`) solo aceptaba password, el login técnico exigía coincidencia exacta de cédula, y el workspace PWA devolvía 403 en escritorio.

## Root Cause

Había dos flujos de autenticación desconectados: oficina usa `Auth::attempt` (email + password hash) y el técnico usa ficha de `staff_tb` (email + cédula). Quien llegaba al login principal ponía la cédula en el campo password y fallaba. Además, `EnsureTechnicianMobile` bloqueaba User-Agents de Windows aunque el login técnico hubiera sido correcto.

## Solution

Se unificó la verificación de técnico (email case-insensitive + cédula normalizada) y se reutiliza desde `/tecnico/login` y como fallback de `/login`. El workspace técnico ya no bloquea escritorio. El admin sigue entrando con correo y password.

## Prevention

- No asumir que el usuario aterriza en la ruta “correcta” de login: si hay dos identidades, el formulario principal debe resolver ambas o redirigir con claridad.
- Tests de login deben cubrir escritorio, cédula con puntos y el formulario de oficina.
- La restricción móvil de una PWA no debe impedir autenticarse durante operación de escritorio si no es un control de seguridad.
